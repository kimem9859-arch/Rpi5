> 리허설(모의 ESP32)로 **배선만** 확인했다. 아래 §3 관문이 촬영 당일의 첫 시험이다.

## 1. 켜는 순서 (🔴 순서가 중요하다)

```bash
# ① 펌웨어 (한 번만 — 이미 구웠으면 건너뛴다)
cd ~/sop-project/Rpi5
PORT=$(python3 Demo/serial_ports.py | grep -oP 'ESP32-S3 → \K\S+')   # ttyACM0 은 인터록이다
arduino-cli compile --fqbn esp32:esp32:XIAO_ESP32S3:PSRAM=opi arduino/glass_voice
arduino-cli upload -p "$PORT" --fqbn esp32:esp32:XIAO_ESP32S3:PSRAM=opi arduino/glass_voice

# ② ESP32 전원 → 부팅 「띠링」이 들리는지 확인
#    🔴 안 들리면 스피커·앰프 전원 문제다. 앰프는 배터리 마디에서 뽑아야 한다(§10.55-(4)).

# ③ 주소 확인
cat Demo/.camera_ip && ping -c2 $(cat Demo/.camera_ip)

# ④ GUI
./Demo/run_demo.sh
#    🔴 **공구 지참 단계(wait_tool)까지 진행한다** — 여기가 아니면 공구 추론이 안 돈다.

# ⑤ 음성비서 (다른 터미널)
./Demo/run_voice.sh
#    「STT 준비됨」 → 「마이크 업링크 연결됨 (…:8889)」 이 나와야 한다.
#    🔑 ESP32 보다 먼저 켜도 된다 — 붙을 때까지 3초마다 다시 시도한다.
```

## 2. 대본

| 말하는 것 | 나와야 하는 것 |
|---|---|
| **"가디언"** | 띠링 (즉시) |
| **"앞에 보이는 게 뭐야?"** | "앞에 〈공구〉가 보입니다." |

⚠️ **한 문장으로 "가디언, 앞에 보이는 게 뭐야?" 라고 해도 동작한다** — 상태기계가 어긋났을 때의 폴백이라 재시도를 줄인다.

## 3. 🔴 촬영 당일이 첫 시험인 관문

| # | 관문 | 확인법 |
|---|---|---|
| **G1** | 마이크+카메라+스피커 동시 초기화 | 부팅 로그에 `Camera OK` · `[OK] 마이크` · `[OK] 스피커` 셋 다 |
| **G2** | 무선 오디오 왕복 | `esp32_audio.py --tcp <IP>:8890 play ...` 가 `ok` |
| **G3** | 업링크 중 FPS ≥ 15 | GUI 영상이 평소처럼 부드러운가 |
| **G4** | 대본 3회 연속 | 로그에 `들림:` 과 `재생 →` 이 짝으로 |
| ⛔ | **명료도** | 답변이 **귀 옆 5cm 에서 알아들리는가**. 나쁘면 문장을 줄여 `make_answers.py` 재실행 |

## 4. 증상별 대응

| 증상 | 먼저 볼 것 |
|---|---|
| **띠링이 안 남** | 데몬 로그의 `들림:` 을 본다. 호출어가 **다른 문자열로 들렸으면** `Demo/voice_lib.py` 의 `WAKE_WORDS` 에 **그 문자열을 그대로 추가**한다. 🔑 실측 오인식을 자산으로 쓰는 것이 이 설계의 방식이다 |
| **말했는데 `들림:` 자체가 없음** | VAD 임계가 높다 → `find_utterance(start_th=600)` 을 400 으로 낮춘다(`voice_assistant.py` 에서 인자로 넘기거나 `voice_lib` 기본값 수정) |
| **문장이 중간에 잘림** | `tail_ms=700` 을 900 으로 올린다 — 문장 중간 쉼이 길다는 뜻이다 |
| **"단계가 아닙니다"** | GUI 가 `wait_tool` 단계인가. 공구 추론은 그때만 돈다 |
| **"공구가 보이지 않습니다"** | 공구를 카메라 화면 안에 두었는가. `tool_v3` 클래스는 `driver`·`wrench`·`pliers` 뿐이다 |
| **아무 반응 없음** | 로그에 `업링크 끊김` → ESP32 재부팅. `.camera_ip` 가 맞는지도 확인. 🔑 **데몬은 안 죽고 3초마다 다시 붙는다** — ESP32 만 살리면 저절로 복구된다(2026-09-06 확인) |
| **오디오가 밀린다** | 로그에 `오디오가 밀려 … 버렸다` → 링크가 나쁘다. ESP32 를 AP 가까이 |

## 5. HW 없이 다시 확인하는 법

```bash
cd ~/sop-project/Rpi5
python3 Demo/selftest/test_voice_lib.py                      # 판정 로직 (1초)

# 모의 ESP32 로 전 구간 리허설 — 진짜 사람 목소리(9/1 녹음)를 쓴다
~/env/tts/.venv/bin/python Demo/test/fake_glass.py ~/lab/tts/phone/p1.wav /tmp/q_tool.wav &
sleep 2 && ~/env/tts/.venv/bin/python Demo/voice_assistant.py --ip 127.0.0.1 --once
```

⚠️ 리허설이 **답하지 않는 것** — ESP32 마이크 음질 · 실제 스피커 명료도 · 링크 안정성 · 카메라와의 동시 가동. 그것들은 §3 관문이다.
