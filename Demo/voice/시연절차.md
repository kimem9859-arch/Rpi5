## 0. 🔴 구성 — 보드가 **둘**이다 (2026-09-06 개정)

| 보드 | 역할 | 펌웨어 | 주소 파일 |
|---|---|---|---|
| **메인 ESP32** | 카메라만 | `camera_stream_tcp` (기존 그대로) | `Demo/.camera_ip` |
| **서브 ESP32** | 마이크·스피커 | **`glass_audio`** (신설) | **`Demo/.audio_ip`** |

🔑 **서브는 카메라만 불량한 예비 본체를 쓴다** — 마이크·I2S·WiFi 는 정상이다(§10.55-(5)).
⚠️ **촬영 시 서브 보드가 화면에 안 들어가게** 둔다(주머니·책상 아래).

## 1. 켜는 순서 (🔴 순서가 중요하다)

```bash
cd ~/sop-project/Rpi5

# ①-a 메인 보드(카메라) — 기존 스크립트 그대로. IP 가 .camera_ip 에 자동 기록된다.
./arduino/flash_esp32.sh

# ①-b 서브 보드(오디오) — 🔴 메인은 빼고 서브만 USB 에 꽂은 상태에서
PORT=$(python3 Demo/serial_ports.py | grep -oP 'ESP32-S3 → \K\S+')   # ttyACM0 은 인터록이다
arduino-cli compile --fqbn esp32:esp32:XIAO_ESP32S3:PSRAM=opi arduino/glass_audio
arduino-cli upload -p "$PORT" --fqbn esp32:esp32:XIAO_ESP32S3:PSRAM=opi arduino/glass_audio
# 부팅 로그에서 IP 를 읽어 .audio_ip 에 적는다
timeout 40 python3 -c "
import serial,re,sys
s=serial.Serial('$PORT',115200,timeout=1)
for _ in range(40):
    ln=s.readline().decode('utf-8','replace')
    m=re.search(r'IP: (\d+\.\d+\.\d+\.\d+)', ln)
    if m: open('Demo/.audio_ip','w').write(m.group(1)); print('오디오 보드 IP =', m.group(1)); break
"

# ② 서브 보드 전원 → 부팅 「띠링」이 들리는지 확인
#    🔴 안 들리면 스피커·앰프 전원 문제다. 앰프는 배터리 마디에서 뽑아야 한다(§10.55-(4)).

# ③ 주소 확인 — 둘 다
cat Demo/.camera_ip Demo/.audio_ip
ping -c2 $(cat Demo/.camera_ip) && ping -c2 $(cat Demo/.audio_ip)

# ④ GUI
./Demo/run_demo.sh
#    🔴 **공구 지참 단계(wait_tool)까지 진행한다** — 여기가 아니면 공구 추론이 안 돈다.

# ⑤ 음성비서 (다른 터미널)
./Demo/run_voice.sh
#    「STT 준비됨」 → 「마이크 업링크 연결됨 (…:8889)」 이 나와야 한다.
#    🔑 ESP32 보다 먼저 켜도 된다 — 붙을 때까지 3초마다 다시 시도한다.
```

## 1.5 🎬 촬영 대본 — 컷 구성 (2026-09-06 확정)

**총 길이 25~35초.** 음성비서는 시연영상에서 비중이 크지 않으므로 **짧고 확실하게** 간다.

| 컷 | 길이 | 화면 | 소리 | 촬영 메모 |
|---|---|---|---|---|
| **①** | 3~4초 | 3인칭 — 글라스를 쓴 작업자가 콘솔 앞에 섬 | (환경음) | 글라스가 보이게. **오디오 보드가 화면에 안 들어오게** |
| **②** | 4~5초 | **1인칭**(글라스 카메라) — 책상 위 공구 3종 | 작업자: **"가디언"** → **띠링** | 🔑 **띠링이 들리는 순간이 이 영상의 핵심**이다. 여기서 끊기면 재촬영 |
| **③** | 5~7초 | 1인칭 유지 — 렌치 쪽을 바라봄 | 작업자: **"앞에 보이는 게 뭐야?"** → **"앞에 렌치가 보입니다."** | 🔴 답이 나오기까지 1~2초 걸린다. **말하고 나서 카메라를 멈추지 말 것** |
| **④** | 3~4초 | 화면 분할 or 컷 전환 — GUI 의 공구 박스 | (없음) | *"비서가 본 것"* 과 *"시스템이 본 것"* 이 같다는 것을 보이는 컷 |
| **⑤** | 5~8초 | GUI 전체 — 순서 위반 시각 경고 | 경고음(기존 타워램프/GUI) | ⚠️ **음성 경고가 아니다**(이번 범위 밖). 분량이 남을 때만 |

### 🔑 촬영 요령
- **②③은 한 번에 이어서 찍는다** — 나눠 찍으면 띠링과 답변 사이의 실제 지연이 안 보여 오히려 부자연스럽다.
- **한 문장 폴백을 예비로 안다** — ②③이 자꾸 어긋나면 **"가디언, 앞에 보이는 게 뭐야?"** 를 한 번에 말해도 동작한다. 컷이 하나 줄지만 확실하다.
- **공구는 3종을 다 두되 렌치를 가운데** — 답변 wav 가 셋 다 준비돼 있어 무엇이 잡혀도 되지만, 대본과 맞추려면 렌치가 유리하다.
- 🔴 **테이크마다 데몬 로그를 본다** — `들림:` 에 뭐라고 찍혔는지가 다음 테이크의 근거다.

### 🔴 찍기 전에 반드시 확인
1. **배터리 충전** — 카메라+오디오면 30~40분이면 바닥난다
2. **`wait_tool` 단계** — 아니면 *"확인하는 단계가 아닙니다"* 만 나온다
3. **띠링이 부팅 때 들렸는가** — 안 들리면 스피커·앰프 전원부터

## 2. 대본

| 말하는 것 | 나와야 하는 것 |
|---|---|
| **"가디언"** | 띠링 (즉시) |
| **"앞에 보이는 게 뭐야?"** | "앞에 〈공구〉가 보입니다." |

⚠️ **한 문장으로 "가디언, 앞에 보이는 게 뭐야?" 라고 해도 동작한다** — 상태기계가 어긋났을 때의 폴백이라 재시도를 줄인다.

## 3. 🔴 촬영 당일이 첫 시험인 관문

| # | 관문 | 확인법 |
|---|---|---|
| ~~G1~~ | ~~셋 동시 초기화~~ | ✅ **해소됨** — 보드를 나눠 이 위험이 사라졌다(2026-09-06 개정) |
| **G2** | 무선 오디오 왕복 | `esp32_audio.py --tcp <IP>:8890 play ...` 가 `ok` |
| **G3** | 업링크 중 FPS ≥ 15 | GUI 영상이 평소처럼 부드러운가. 🔑 **보드가 나뉘어 위험이 크게 줄었다** — 이제 같은 칩이 아니라 **같은 AP 를 나눠 쓰는 문제**이고, 대역은 영상 242~280 + 오디오 75KB/s 로 링크의 약 4%다(§10.55-(2)) |
| **G4** | 대본 3회 연속 | 로그에 `들림:` 과 `재생 →` 이 짝으로 |
| ⛔ | **명료도** | 답변이 **귀 옆 5cm 에서 알아들리는가**. 나쁘면 문장을 줄여 `make_answers.py` 재실행 |

## 4. 증상별 대응

| 증상 | 먼저 볼 것 |
|---|---|
| **띠링이 안 남** | 데몬 로그의 `들림:` 을 본다. 호출어가 **다른 문자열로 들렸으면** `Demo/voice_lib.py` 의 `WAKE_WORDS` 에 **그 문자열을 그대로 추가**한다. 🔑 실측 오인식을 자산으로 쓰는 것이 이 설계의 방식이다 |
| **말했는데 `들림:` 자체가 없음** | VAD 임계가 높다 → `find_utterance(start_th=600)` 을 400 으로 낮춘다(`voice_assistant.py` 에서 인자로 넘기거나 `voice_lib` 기본값 수정) |
| **문장이 중간에 잘림** | `tail_ms=700` 을 900 으로 올린다 — 문장 중간 쉼이 길다는 뜻이다 |
| **"단계가 아닙니다"** | GUI 가 `wait_tool` 단계인가. 공구 추론은 그때만 돈다 |
| **"공구가 보이지 않습니다"** | 공구를 카메라 화면 안에 두었는가. `tool_v3` 클래스는 `driver`·`wrench`·`pliers` 뿐이다 |
| **아무 반응 없음** | 로그에 `업링크 끊김` → ESP32 재부팅. `.camera_ip` 가 맞는지도 확인. 🔑 **데몬은 안 죽고 3초마다 다시 붙는다** — ESP32 만 살리면 저절로 복구된다(2026-09-06 확인) |
| **오디오가 밀린다** | 로그에 `오디오가 밀려 … 버렸다` → 링크가 나쁘다. ESP32 를 AP 가까이 |

## 5. HW 없이 다시 확인하는 법

```bash
cd ~/sop-project/Rpi5
python3 Demo/selftest/test_voice_lib.py                      # 판정 로직 (1초)

# 모의 ESP32 로 전 구간 리허설 — 진짜 사람 목소리(9/1 녹음)를 쓴다
~/env/tts/.venv/bin/python Demo/test/fake_glass.py ~/lab/tts/phone/p1.wav /tmp/q_tool.wav &
sleep 2 && ~/env/tts/.venv/bin/python Demo/voice_assistant.py --ip 127.0.0.1 --once
```

⚠️ 리허설이 **답하지 않는 것** — ESP32 마이크 음질 · 실제 스피커 명료도 · 링크 안정성 · 카메라와의 동시 가동. 그것들은 §3 관문이다.
