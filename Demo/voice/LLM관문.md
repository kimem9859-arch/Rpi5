## 0. 🔴 새 환경에서 먼저 할 일 (둘 다 안 하면 이하 전부 무의미)

### 0.1 폴백 wav 를 만든다

`.gitignore` 29행이 `*.wav` 라 **폴백 wav 가 저장소에 안 들어간다.** 새로 클론한 환경(또는
`Demo/voice/wav/` 를 지운 환경)에서 이걸 건너뛰면 **폴백이 침묵이 된다** — 「모든 실패의
착지점이 A 갈래」라는 설계 전체가 무너진다(spec §10).

```bash
cd ~/sop-project/Rpi5
~/env/tts/.venv/bin/python Demo/voice/make_answers.py     # wav 9종 생성 (필수)
ls Demo/voice/wav/                                        # checking·notready·changed·unavailable 확인
```

①무엇을 한다 — 위 두 명령을 그대로 돌린다.
②무엇이 보이면 통과 — `ls` 출력에 `checking.wav`·`notready.wav`·`changed.wav`·`unavailable.wav`
네 개가 **전부** 보인다(기존 A 갈래용 5종에 더해).
③안 되면 무엇을 본다 — `make_answers.py` 가 에러로 죽었는지 콘솔 출력을 본다. 대개
`~/env/tts` venv 가 없거나 `sherpa_onnx` 미설치다.

### 0.2 pi2 의 ollama 를 연다

Task 8(G2~G4)·이 문서의 G2~G4·G7~G9 전부의 전제다. 기본값 `127.0.0.1` 바인딩이면
파이(sop-pi)에서 붙을 수 없다(HTTP 000).

```bash
ssh pi2 'sudo systemctl edit ollama'      # [Service] 아래 Environment="OLLAMA_HOST=0.0.0.0"
ssh pi2 'sudo systemctl restart ollama'
curl -s http://192.168.1.12:11434/api/tags | head -c 200    # 응답이 오면 열린 것
```

①무엇을 한다 — 위 세 명령. 편집기에는 `[Service]` 섹션 아래에 그 한 줄만 추가한다.
②무엇이 보이면 통과 — `curl` 이 JSON(`{"models":[...`)을 돌려준다.
③안 되면 무엇을 본다 — `curl: (7) Failed to connect` 면 재시작이 아직 안 먹은 것이다
(`ssh pi2 'systemctl status ollama'` 로 `Environment=` 가 실제로 박혔는지 재확인).

## 1. 관문 순서 (G6 → G11, 하나씩)

> 판정표·출처 대조는 `spec §12`. 여기는 **손으로 도는 절차**만 적는다.

### G6 검산 (판정은 selftest, 동작은 실HW)

①무엇을 한다 — 실HW 로 대본을 돌리다가, LLM 답변이 합성되는 도중 **일부러 카메라
앞의 공구를 바꿔 쥔다**(또는 GUI 로 단계를 넘긴다). `voice_assistant.py` 로그를 본다.
②무엇이 보이면 통과 — 로그에 `⚠️ 검산 불일치 [...] — 합성한 소리를 버린다: <문장>`
가 찍히고, 대신 `changed` 나 새 공구 답이 재생된다. `계측.jsonl` 의 `검산` 필드에
바뀐 항목 배열(`["공구"]` 등)이 남는다.
③안 되면 무엇을 본다 — 어긋난 문장이 그대로 재생됐으면 `voice_card.verify_answer()`
가 그 유형(공구/단계/버튼/상태/세션)을 대조 목록에 안 넣었을 수 있다 —
`voice_card.py` 의 `verify_answer()` 를 본다.

### G7 E2E 지연 계측 (판정 아님 — §1.3 「사람이 해야 하는 것」참조)

①②③은 아래 §2 「G7·G9 실측」에 있다. 여기서는 **계측만** 한다 — 통과/실패 판정이 아니다.

### G8 깨어남 (작업 전 LLM 0회)

①무엇을 한다 — GUI 로 세션을 **시작하기 전**에 「가디언, 앞에 보이는 게 뭐야?」라고
말한다.
②무엇이 보이면 통과 — 답이 **즉시**(LLM 지연 없이) `notready` 로 나오고,
`계측.jsonl` 에 `"답변출처": "고정-작업전"` 이 찍히며 `LLM_ms` 필드 자체가 없다
(LLM 을 아예 안 불렀다는 뜻).
③안 되면 무엇을 본다 — `계측.jsonl` 레코드에 `LLM_ms` 키가 찍혔거나 `LLM사용`
이 `true` 로 나오면 LLM 을 불렀다는 뜻이다 — `voice_assistant.py` 의
`if not facts["세션"]:` 분기가 `ask_async()` 호출보다 **앞**에 있는지 코드
순서를 본다.

### G9 동시성 (실HW 필요)

①②③은 §2 「G7·G9 실측」과 같은 회차에서 뽑는다 — `LLM_ms` 가 발화 처리 전체 시간
대비 얼마를 차지하는지 `계측.jsonl` 로 계산한다(별도 절차 없음, G7 계측과 같은 로그).

### G10 생성 문장 발음 (🔴 사람 귀가 필요한 유일한 관문)

①②③은 아래 §2 「G10 발음 청취」에 있다.

### G11 처리 중 발화 (구조 확인)

①무엇을 한다 — 「확인해 보겠습니다」(`checking`)가 재생되는 동안, 즉 아직 답이
안 나온 사이에 **한 번 더** 말을 건다.
②무엇이 보이면 통과 — 두 번째 발화가 답변으로 처리되지 않는다. 로그에 새 `들림:`
줄이 아예 없거나(버려짐), 있어도 다음 호출어를 기다리는 대기 상태로 돌아간다.
③안 되면 무엇을 본다 — `voice_assistant.py` 의 `finally: del buf[:]` 가 LLM
스레드 join 뒤에 실제로 도는지 본다(구조상 두 번째 호출이 불가능하도록 설계돼
있어, 이게 깨졌다면 그 사이에 코드가 바뀐 것이다).

## 2. 사람이 해야 하는 것 셋

### GUI 버튼 (Task 2 에서 넘어온 항목 — 마우스 필요, 단축키 없음)

①무엇을 한다 — `./Demo/run_demo.sh` 로 GUI 를 띄우고 **「▶ 작업 시작」을 마우스로
누른다.**
②무엇이 보이면 통과 — `cat /dev/shm/sop_state/state.json` 에 `"세션": true` 와
`"현재단계": 1` 이 나온다. 이어서 단계를 넘기면(버튼을 누르거나 인터록을 통과하면)
`현재단계` 값이 바뀐다.
③안 되면 무엇을 본다 — 파일 자체가 없으면 `state_publisher.py` 가 `safety_console.py`
에서 실제로 불리는지(삽입 지점이 빠졌는지) 본다. 파일은 있는데 `세션`이 그대로
`false` 면 버튼 클릭 이벤트가 publisher 호출까지 안 이어진 것이다.

### G10 발음 청취

①무엇을 한다 —

```bash
~/env/tts/.venv/bin/python -c "
import sys; sys.path.insert(0,'/home/pi/sop-project/Rpi5/Demo')
from voice_tts import Tts
t = Tts()
for s in ['다음은 3단계인 전극 냉각으로 넘어가기 위해 버튼 B3를 누르시면 됩니다.',
          '2단계의 서브작업인 N2 퍼지 10초에 필요한 공구는 렌치입니다.']:
    print(s, t.synth(s)[2])"
```

들어 본다.

②무엇이 보이면 통과 — `B3`·`N2` 가 사람이 알아들을 수 있게(「비 삼」·「엔 투」에
가깝게, 최소한 뜻이 통하게) 읽힌다.

③안 되면 무엇을 본다 — 안 들리면(알파벳+숫자를 이상하게 읽으면) 대응 둘 중 하나:
- (가) `voice_llm.SYSTEM` 에 *"버튼 이름은 「비 삼」처럼 한글로 읽어 쓴다"* 를 넣는다
- (나) `voice_tts` 합성 앞에 치환표를 둔다(`B3`→`비 삼`, `N2`→`엔 투`)

⚠️ **A 갈래에 없던 위험이다** — A 갈래 고정 답변 5개는 전부 순한글이라 이 문제가
없었다. LLM 이 카드의 `B3`·`N2` 표기를 그대로 답변에 옮기면서 처음 생긴다.

### G7·G9 실측

①무엇을 한다 — 실HW 로 대본을 여러 차례 돌리고(§1.5 대본 참고, `SOP_VOICE_METRICS`
환경변수로 `계측.jsonl` 경로를 지정해 둔다), 로그를 모은다.
②무엇이 보이면 통과 — `계측.jsonl` 의 각 발화 레코드에서:
  - **「첫 소리까지」** = `띠링_ms` + `STT_ms` + `LLM_ms`(있으면) + 합성·전송 준비 시간
    (재생 명령이 나가기 직전까지)
  - **「다 듣기까지」** = 위 + `말하는초`(TTS 가 실제로 말하는 길이)
  둘을 **따로** 뽑아 기록한다. 하나로 뭉치지 않는다(§10.49 함정 재발 방지).
  동시성(G9)은 `LLM_ms` 를 전체 시간으로 나눠 비중을 본다.
③안 되면 무엇을 본다 — `계측.jsonl` 이 비어 있으면 `SOP_VOICE_METRICS` 환경변수가
안 걸린 것이다. 필드가 빠져 있으면(`LLM_ms` 없음) `LLM사용` 이 `false` 였다는
뜻이니 `config.LLM_ENABLED`(`SOP_LLM` 환경변수)와 pi2 연결(§0.2)을 먼저 본다.

## 3. 증상별 대응

| 증상 | 먼저 볼 것 |
|---|---|
| **띠링은 울리는데 답이 없다** | `계측.jsonl` 의 `답변출처` 를 본다. `고정-폴백` 이면 LLM 호출 자체가 실패한 것 — §0.2(pi2 열림)부터 확인. `고정-검산불일치` 면 §1 G6 항목대로 카드-답변 어긋남이다 |
| **늘 `고정-폴백` 으로만 답한다** | `curl -s http://192.168.1.12:11434/api/tags` 가 응답하는지(§0.2). 응답하면 `voice_llm.ask()` 의 타임아웃(`config.LLM_TIMEOUT_SEC`)을 늘려 본다 — pi2 가 다른 요청으로 바빠 그 값을 넘기고 있을 수 있다 |
| **`작업 시작되지 않음` 이라고만 한다** | GUI 로 「▶ 작업 시작」을 실제로 눌렀는지(§2 GUI 버튼 항목). `state.json` 의 `세션` 값을 직접 확인 |
| **답이 한참 지나도 안 나온다** | `계측.jsonl` 에 레코드 자체가 안 남았으면 데몬이 멈췄거나 예외로 죽은 것 — 콘솔 로그를 본다. 레코드는 남는데 `말하는초` 가 비정상으로 크면 TTS 합성이 아니라 **답변 문장 자체가 너무 길다**(spec §10 의 길이 제한이 우회된 것) — `voice_llm.SYSTEM` 의 두 문장 제한 문구가 살아 있는지 본다 |
| **`검산 불일치` 가 너무 자주 뜬다** | 「확인해 보겠습니다」가 재생되는 동안 상태가 자꾸 바뀌는 것 — 시연에서는 정상 동작이다(설계 의도, LLM 이 답을 만드는 사이 대본이 앞서 나간 경우). 오검출이라면 `voice_card.verify_answer()` 가 답변에 안 나온 사실까지 대조하고 있는지 확인 |
| **G10 에서 `B3`·`N2` 가 안 들린다** | §2 G10 발음 청취 항목의 대응 (가)/(나) |

## 4. HW 없이 다시 확인하는 법 (판정 아님 — 배선 재현용)

```bash
cd ~/sop-project/Rpi5
python3 Demo/selftest/test_voice_card.py     # 카드·검산 로직 (G1·G6 판정 조각)
python3 Demo/selftest/test_voice_llm.py      # LLM 호출 폴백 로직 (G5 판정 조각)
~/env/tts/.venv/bin/python Demo/selftest/test_voice_tts.py
```

⚠️ **리허설이 답하지 않는 것** — pi2 의 실제 응답 속도·네트워크 지연(G2~G4·G7·G9),
사람 귀에 들리는 발음(G10). 그것들은 위 §1·§2 관문이다.
