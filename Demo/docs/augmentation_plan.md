# console_v2 증강 계획 — 검정→파랑 버튼 전환 반영

> console_v2 **GPU 재학습 시점**에 적용할 증강 스펙. 파이가 아니라 **GPU 머신(x86/CUDA)에서 Ultralytics 학습 시** 사용한다.
> 짝 문서: 데이터 재현 = `dataset_pipeline.md`, 라벨링 = `labeling_guide.md`.
> ⚠️ 측정 수치의 정본은 **통합문서 §10** — 여기는 "왜·무엇을" 스펙만, 수치는 §참조.

## 언제 쓰나 (파이프라인 위치)
```
✅ 라벨링(652장) → ① 검수 → ② YOLO export → ③ GPU 재학습 ★증강 여기★ → ④ DFC 변환(.pt→.hef) → ⑤ replay_raw 평가
```
증강은 별도 단계가 아니라 **③ 학습의 일부**다(§10.13: "증강은 Roboflow가 아니라 학습 코드에서" — 실시간 Albumentations가 매 epoch 다른 변형을 보여 오프라인보다 효과적).

---

## 1. 왜 다시 세우나 (전제 소멸)
기존 증강 처방(§10.9)은 **검정 B4** 전용이었다: "검정 on 검정 → 고주파 경계에만 의존 → **블러·JPEG·저해상도 증강**으로 그 의존을 깨라".

§10.12에서 **B4에 파랑 원 스티커**를 붙여 **색-의존 클래스로 이동**했다. 실측상 블러 σ3.0·JPEG q12·해상도 25%에도 채도 대비가 무손상(수치 §10.12). → **고주파 열화 증강의 목표가 소멸**했다.

**핵심 전환: 이제 5클래스 전부 색-의존이므로, 증강이 방어할 적은 "고주파 손실(블러/JPEG/저해상도)"이 아니라 "색 손실(저조도 ≫ 정반사)"이다.**

## 2. ESP32 실제 문제점 (파랑 raw 기준)
| # | 문제 | 상태 | 근거 |
|---|---|---|---|
| 1 | B4 고주파 사멸 | ✅ **해소**(파랑=저주파 색) → 열화증강 불필요 | §10.12 |
| 2 | **저조도**(밝기·채도↓) | ⭐**실재 주력 위협** — B3 완전사멸·EMO 반감 | §10.13 세션 180016 |
| 3 | 정반사(색→흰 포화) | **경미·조건부** — AE가 방어(포화 1%), B4 최내성 | §10.8·§10.13 |
| 4 | Hue 변화 | 증강 **금지**(색이 클래스 정의) | §10 학습설정 |
| 5 | FPS 미달·실콘솔 재질 | 증강으로 못 푸는 **별개 문제**(범위 밖) | §10.11·§10.8 |

⚠️ **미측정 플래그**: 저조도에서 **파랑 B4 생존 여부는 아직 미측정**(v1 프리라벨 0). → ⑤ 평가에서 저조도 세션(180016) raw로 확인할 것.
⚠️ **AE 주의**: ESP32 AE가 조명 극단을 자체 방어(§10.13)하므로 배포 조명 분포가 학습보다 좁을 수 있음 → 극단 광량 증강은 과하지 않게.

## 3. 증강 스펙

### 3-A. 광도(photometric) — 색 손실 방어가 핵심
| 증강 | 우선순위 | 강도(초안) | 근거 |
|---|---|---|---|
| **저조도** (밝기↓ + 채도↓ + 센서노이즈 동반) | ⭐**주력** | 밝기 ×0.3~1.0, 채도 ×0.6~1.0, GaussNoise | §10.13 B3 사멸 = 유일 실측 실패 |
| **정반사/하이라이트 합성** (국소 포화) | 보험(소량) | p=0.2~0.3, 소면적 blowout | §10.8 조건부·AE 방어 |
| 센서노이즈(ISO) | 보조 | 저조도와 결합 | 저조도 시 노이즈 동반 |
| 블러·JPEG·저해상도 | **강등**(약하게만) | 일반 견고성 정도 | 파랑 무손상(§10.12) |
| **Hue jitter** | ❌**금지** | `hsv_h=0` | 색이 클래스 정의(§10) — 파랑↔B3핑크↔EMO빨강 혼동 유발 |

> ※ 정반사 "합성"은 **국소 하이라이트**(빛나서 색이 날아간 상황을 가르침)이지 전역 색상 변경이 아니다 — Hue 금지와 충돌하지 않는다.

### 3-B. 기하(geometric) — 위치 지름길 방어
| 증강 | 강도(초안) | 근거 |
|---|---|---|
| translate / scale | 중간 | 프레임 위치 편향 차단 |
| 소폭 회전 `degrees` | **±10~15°만** | 헤드캠 기울기. 180° 뒤집기 금지(정립 배포) |
| mosaic | Ultralytics 기본 유지 | 위치 편향 완화 |
| **EMO 상대위치** | 증강 불가 → **데이터로** | 강체증강으로 못 바꿈. 실콘솔 EMO 위치가 모조와 다름 |

### 3-C. 적용 방식
- **Ultralytics 하이퍼파라미터**: `hsv_h=0`(필수) / `hsv_s`·`hsv_v` 소폭 / `degrees=10~15` / `translate` / `scale` / `mosaic`(기본).
- **커스텀 Albumentations 훅**: Ultralytics에 **없는** JPEG압축·정반사 합성·저조도 채도강하를 보완.
- **평가 도구 재사용**: `test/replay_raw.py`의 `_jpeg/_blur/_resample`(`--ablation`)은 **증강이 아니라 평가용** — 학습된 모델을 열화 프레임에 돌려 검증.

## 4. 검증 (증강 효과 확인법) — 🔴 판정 기준 정본 = 통합문서 **§10.16**
- ~~B3·B4 검출률이 **v1 대비 상승**했는지 확인~~ → **이 기준은 무의미하다**(2026-07-16 정정). `test/raw/<세션>`이 곧 **학습 데이터의 출처**라(`dataset_pipeline.md`) 학습에 쓴 이미지로 시험 보는 셈이고, v1은 **파랑 스티커를 학습한 적이 없어**(§10.12) 0%가 예정돼 있다. **"v1 0회 → v2 N회"는 자동으로 나온다.**
- ✅ **대신**: ①**하한선**(자기 학습 데이터에서도 B4 실패 시 즉시 중단) ②**⭐세션 간 비교** — 누출이 4세션에 균등해 상쇄되므로 **저조도 `180016`만 무너지면 = 조명 탓**(증강이 저조도를 방어했는지 보는 **유일한 유효 신호**) ③**`.hef` vs `.pt` 대조**(양자화 손실 분리).
- ⚠️ `replay_raw.py`엔 **정답이 없다**(검출 수·confidence만) → 증강 효과의 정량 평가는 불가. 경향만 본다.
- **최종 정직 채점 = test 세션**(다른 날·다른 조명·실콘솔, §10.13 남은 것) — 이것 없이는 증강 효과도 성능도 확정할 수 없다.

## 5. 미해결
- 저조도 파랑 B4 생존 여부 미측정 → 위 검증에서 확인.
- GPU 학습 환경 미정(데스크톱 GPU / Colab / 클라우드). **Roboflow Train은 커스텀 증강 불가라 배제**(§10.13).
