1500장은 **그대로 보존**되어 있고, 여기 있는 것은 전부 **복사본**이다.

원본 1500장 → pHash 중복 제거 → 고유 495장 → 배분 → **흔들림 제거 43장** → **최종 452장**.

|---|---|---|---|---|
| 154730 | 좌우+위아래 각도 | 93 | 3 (3%) | 90 |
| 154851 | 원근거리 | 74 | 4 (5%) | 70 |
| 154947 | 가림 | 126 | **26 (21%)** | 100 |
| 155039 | 카메라+콘솔 회전 | 107 | 9 (8%) | 98 |
| 155119 | 좌우각도 | 95 | 1 (1%) | 94 |
| **합계** | | **495** | **43 (8.7%)** | **452** |

**split별 최종 = test 113 / train 275 / valid 64** (배분 시점 130/292/73에서 흔들림분이 빠진 결과)

- 파일명 = `<순위>_s<선명도>_<원본명>.png` — 순위는 **흐린 순 검토용 정렬 접두**이며 업로드 시 제거된다
- 세 폴더 간 **파일 중복 0건**, `_unique` 대비 **유실 0건** 확인
- 155119는 154730과 좌우각도가 겹쳐 test 할당을 20장으로 줄였다

### 흔들림 제거 (2026-07-20, 사용자 육안 검토)

기준 = **v2 때와 동일** — 잔상이 보이거나 흔들림이 심하면 제거. v2는 848 → 652장(**23.1%**)이었으나 이번은 **8.7%**로 적다. **촬영 시 카메라 흔들림을 의식하고 찍은 결과**다(v2 촬영은 고려하지 않았음).

- 선명도(라플라시안 분산) 중앙값: 제거분 **17.2** / 잔존분 **32.4** — 판단이 일관됨
- 단 **기계적 임계값 절단이 아니다** — 제거분의 최고 선명도(57)보다 흐린 잔존 이미지가 **414장**이다. 한 장씩 "버튼을 식별할 수 있나"로 판단한 결과이며, 선명도 분포가 연속적이라(8~97, 단봉) 자동 임계값은 애초에 쓸 수 없었다.
- `154947`(가림)에 26장이 몰린 것은 손이 움직이며 찍혀 잔상이 생기기 쉬운 세션이기 때문이다.

⚠️ **Roboflow 화면은 미리보기를 축소해 보여준다**(원본은 보존되어 학습에 쓰임). 파이에서 선명해 보여도 사이트에서 흐릴 수 있어 **라벨링 중 소수 추가 제거가 있을 수 있다** — 그때 이 문서와 아래 비율을 갱신할 것.

### ⭐ 분할 비율은 병합 데이터셋 기준으로 판단한다

신규 452장만 보면 valid(64) < test(113)로 어색하지만, 이 이미지들은 **v3 학습 때 v2의 652장과 병합**된다:

| | train | valid | test | 합계 |
|---|---|---|---|---|
| v2 기존 | 522 | 130 | 0 | 652 |
| 신규 | 275 | 64 | 113 | 452 |
| **v3 합계** | **797** | **194** | **113** | **1,104** |
| 비율 | 72.2% | 17.6% | 10.2% | **≈ 7:2:1** |

병합 기준으로는 표준 비율이고 valid > test 순서도 정상이다. **보충 촬영은 불필요하며, 가능하지도 않다** — `_unique` 495장이 1500프레임의 고유 프레임 전부라 여분 풀이 없다(중복 제거 임계를 낮추면 거의 같은 프레임이 들어와 학습 기여 없이 누출 위험만 는다).

## 배분 규칙

- **세션마다 나눠 할당** — 세션 단위로 통째 가르지 않았다. 각 세션이 서로 다른 촬영 변화(각도·원근·가림·회전)라, 세션을 통째로 test에 주면 **그 변화 축이 학습에서 빠지고** 반대도 마찬가지다.
- **균등 간격 추출** — 시간축 전체에 고르게. 한 구간만 뽑으면 그 세션의 변화 범위를 다 못 담는다.
- `valid` = train 잔여의 20%. 재학습 시점에 다시 뽑아도 된다(고정값 아님).

## ⚠️ 취급 규칙

- **test 130장은 절대 학습에 넣지 않는다.** 넣는 순간 채점 결과가 무효가 된다.
- **test는 모델 프리라벨을 쓰지 않는다** — 평가 대상 모델(v2)로 정답을 만들면 모델의 오류를 사람이 "정답"으로 승인하게 되어 채점이 순환논리가 된다. 전량 수동 라벨링.
- `train`·`valid`는 v2 프리라벨(`test/export_labels.py`)을 써도 된다. 학습 데이터이므로 순환 문제가 없다.

### 프리라벨 검수 우선순위

프리라벨은 **v2 자신의 출력**이라 검수 없이 학습하면 v2의 오류를 물려받는다.

1. **빠진 박스 채우기**(필수) — 가장 해롭다. 라벨이 없으면 학습은 그 자리를 "버튼 없음"으로 가르친다.
   - ⚠️ **단 "가려서 없는 것"과 "모델이 놓친 것"을 구분할 것.** 5개 미만인 이미지 76장(22%) 중 **53장이 `154947`(가림) 세션**이며, 가려서 안 보이면 라벨이 없는 게 정답이다(Modal — `labeling_guide.md` §③).
2. **잘못된 클래스 수정**(필수) — 정답은 **진짜 버튼 정체**다.
3. **박스 타이트함**(여유 시) — v2 박스는 사람이 그린 652장으로 학습된 것이라 이미 사람 스타일에 가깝다. 다만 눈에 띄게 어긋난 것은 고칠 것 — FSM이 ROI 겹침으로 손-버튼 접촉을 판정하므로(§7~§9) 박스가 크면 오판할 수 있다.

## 🔴 알려진 한계

`train`/`valid`와 `test`가 **같은 세션에서 나왔다.** 같은 세션은 배경·조명이 고정이고 연속 촬영이라, 중복 제거를 거쳐도 완전히 독립적이지 않다. 따라서 **추후 재학습 후의 채점은 낙관적으로 나온다.**

→ 정식으로 "클린룸에서 쓸 수 있다"를 주장하려면 **재학습 시점에 새로 촬영한 test 세션**이 필요하다. 오늘 데이터로는 거기까지 갈 수 없다.

※ **현재 v2 채점에는 이 한계가 없다** — v2는 7/13 촬영분 652장만 학습했고 클린룸 이미지는 한 장도 들어가지 않았다. 지금 test 130장은 완전한 홀드아웃이다.
