# 조사보고서 원문 대조 (HEF 변환, 2026-10-04)

- **대상**: `조사보고서.md`, `변환설정.json` (같은 폴더)
- **방법**: 주장마다 인용된 1차 출처를 직접 열어 대조했다. 데스크톱 쪽은 `ssh wsl-train` 으로 파일 읽기(`sed -n`·`grep`)만 했다. Model Zoo 는 `git show HEAD:<경로>` 로만 읽었다. 웹 출처는 `curl` 로 받았다: GitHub raw·API, Discourse JSON(`/t/<id>.json`), docs.ultralytics.com, docs.nvidia.com, hailo.ai.
- **하지 않은 것**: DFC·hailo 명령, 컴파일·최적화·내보내기, pip 설치, GPU 작업. `convert_to_hef.sh`, `/mnt/d/Hailo_DFC/` 의 Model Zoo 밖 파일, `dev/ai_model/`, Model Zoo 로컬 수정분은 열지 않았다. 데스크톱에서는 `nvidia-smi` 질의 1회(읽기)만 했다.
- **판정**: ✅ 맞음 · 부분(무엇이 다른지) · 미확인(근거를 열 수 없음과 그 이유) · ❌ 틀림
- **부수효과**: 데스크톱 `/tmp/mu.py` 를 실수로 한 번 만들었다가 바로 지웠다. 그 밖의 다운로드는 파이 scratchpad 에만 받았다.

## 보고서에 필요한 정정

1. **§1 행 번호 두 곳.** `NMSModel` 은 `exporter.py:1134` → **:1126** 이다. ONNX `quantize=8` 정적 양자화는 `:1091` → **:1204-1209**(`onnx_int8_quantize`, `utils/export/onnx.py:70` `quantize_static`)이다.
2. **§1·함정 2·json `onnx._비고`: 자동 설치 목록.** simplify=True 면 onnx·onnxslim 과 함께 **onnxruntime**(cuda 장치면 onnxruntime-gpu)도 설치된다. uv 가 있으면 uv 를 쓴다.
3. **§1 표 「무엇에 맞춘 값인가」.** simplify 「ORT 성능」과 요약 1 「기본값은 ONNX Runtime 용」은 opset 만 원문 근거가 있다. 나머지는 해석이라고 표시하거나 빼야 한다.
4. **§2.2 `has_gpu` 문장.** 「…에서만 쓰인다」를 「수준을 막는 데는 쓰이지 않는다」로 고친다. GPU 가용성은 `subprocess_wrapper.py:81-90`, `tf_utils.py:126`, `sdk_backend.py:1268` 에서도 쓰인다.
5. **§2 NMS 상대경로, json `alls._비고`.** .alls 기준 상대경로가 되는 것은 `load_model_script(<파일 경로>)` 일 때뿐이다. 문자열로 넣으면 `_path=None` 이 되어 **현재 작업 폴더 기준**이다(`model_script_parser.py:135,310`, `nms_postprocess_command.py:302-307`). 오류 문구 위치는 `:538` 이다. 스크립트 설계에서 절대경로를 쓰거나 alls 를 파일로 넣도록 정해야 한다.
6. **§2 NMS 「못 찾으면 *Cannot infer…*」.** 이 문구는 분기 층 수가 맞지 않거나 `classes == 1` 일 때 난다. 분류 채널이 `classes` 와 다르기만 하면 `cls_layer` 는 빈 칸으로 남고, 그 자리에서는 오류가 나지 않는다.
7. **§6 짝 표 v2.19.0 줄.** HailoRT 「—」 → **4.24.0**(v2.19.0 README 배지). v2.18 README 배지와 `GETTING_STARTED.rst:12` 도 DFC 3.33.0 으로 적혀 있어, 문서끼리 어긋나는 것은 v2.18 도 마찬가지라고 덧붙일 수 있다.
