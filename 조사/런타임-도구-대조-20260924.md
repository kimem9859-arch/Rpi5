## 5. 우선순위 (중요한 것부터)

1. **H — 사전 감지·체류·차단 계열 도구가 RT 추적을 안 쓴다**(dwell_probe·hoi_probe_batch/hoi.db/fsm_sim·b3emo): rawdet 박스, 가림 유지 없음, 검출 0 프레임 처리가 도구마다 다름. G3·§12.67 결론에 직결. → 권고: RT 추적 함수를 순수 모듈(roi_zones 처럼)로 빼서 도구가 import.
2. **H — dwell_probe 는 FSM 이 아니다**: 비인과 갭메우기, 링·정답 ROI 포함 체류, 발화 조건 없음. fsm_sim 관문도 이 재구현에 기대 있음.
3. **H — bench_detector `_one_per_class` 부재**: 확정 트랙 수·detection_count·stability·bench.db detections 부풀림(36% 프레임).
4. **H — G2 FPS 측정 조건·통계**: 순간 FPS 평균(+~4%), 창/녹화/PNG 부하 혼입, GUI 부하 부재. 재측정 전 `--headless` 와 1/중앙값(또는 처리량) 병기 필요.
5. **H(과거)/M — bench `--undistort` 기본 꺼짐**: RT 와 다른 입력 기하. 과거 raw 재분석 시 manifest 확인 필수(replay_raw·dwell_probe 가 안 봄).
6. **M — hoi.db flag 필터 미적용**(3.8% zone 프레임) · **팜 임계 0.5 가 config 밖**(blaze 기본값에 의존).
7. **M — RT 손 입력에 YOLO 오버레이가 그려져 있다**(도구는 깨끗한 프레임): 차이의 원인은 RT 쪽. 버튼 근처 손끝 검출에 영향 가능 — 미측정. (`SHOW_DETECT_BOXES` 토글이 판정을 바꿀 수 있다는 뜻이기도 함 — config 주석 「표시만 끈다」와 어긋남.)
8. **M — 공구: RT 는 JPEG q80 재압축 입력**, holdout_score·tool_live 는 아님 · tool_live 는 보정 없음·conf 0.60.
9. **M — B4↔EMO/confusion 지표는 구조적으로 항상 0**인데 bench 요약에 찍힌다.
10. **L — 하드코딩 복제**(CLASS_NAMES·색·TIP·경로·CONF_WARN·dwell 을 config vs recipe.json 에서 따로 읽음).
