## 재학습 모델 3종 NPU 동시 — 정지 장면 속도·NPU 사용량 (2026-10-06 14:4x · 출발 전 · 조작 없음)

> 사용자 「재학습한 버튼, 공구 모델 … 버튼, 공구, 손 모델을 한번에 돌려 성능 확인」 · 「현재 카메라가 바라보고 있는 화면으로 카메라 고정 속도 측정만」 · 「npu 자원 사용량도 같이」. 장소2 시험(손·공구가 보이는 장면)은 아직이다.

- **조건** — 장소1(학교 사무실) 책상 위에 놓인 안경 · 천장·사무실이 보이는 **정지 장면 · 손·공구·콘솔 없음**(손 랜드마크 모델은 한 번도 안 돎) · XGA · 왜곡보정 켬 · **PNG 저장 없음** · 화면 표시 켬 · 300프레임 × 3회 · 조합을 번갈아(A·B·C 를 r1→r3) · D 는 그 뒤 3회 · 단일 세션. `HAILO_MONITOR=1` + `hailortcli monitor`(측정 12초 뒤 7초) · 파이 CPU·온도 = psutil·vcgencmd 1초.
- **모델** — A 현행 `console_v2.hef`(+손) · B 재학습 버튼 `B-early-base-s0`(E0b HEF)+손 · C B+공구 `T-full-base-s0`(E0c HEF) **매 프레임** · D C 와 같되 공구 **1초에 한 번**(시연 `TOOL_SCAN_INTERVAL_SEC`). ⚠️ A 에는 시연의 CPU 공구 워커(tool_v3.pt)가 없다 — 「현행 시연 전체 부하」가 아니다.
- **표** = `npu_정지장면_표.md`(재현 = `python3 npu_정지장면_계산.py` · 원자료 `npu_원자료/` · 측정 스크립트 사본 `npu_정지장면_측정.sh` 는 작업 폴더 경로 그대로).

- **NPU 는 남는다** — C 에서도 장치 사용률 44~48%(모델별 버튼 18~19% · 손바닥 8~9% · 공구 18~20%). 파이 CPU 20~28% · 온도 최고 51.6℃. C 의 FPS 하락(약 18.5 → 13.3 = 한 프레임 약 54 → 75ms)은 공구 추론 시간(평균 18.8ms)이 **한 프레임 안에 차례로 더해진 것**과 크기가 같다 — 장치가 모자라서가 아니라 버튼 → 손 → 공구를 **차례로 기다리는** 구조 탓으로 보인다(정황 · 같은 크기 대조뿐).
- **D 의 공구 직후** — 공구를 돌린 다음 프레임 하나가 느려진다(약 18 → 12~14fps · 3회 모두). 버튼 추론 시간은 공구 전후 같다(약 18.8ms) → NPU 가 모델을 바꿔 끼우는 비용의 흔적은 없다. D r1·r2 의 긴 연속 저하(8·7)는 공구 직후 한 장으로 설명되지 않고, 이 데이터로 원인을 가를 수 없다(3회).
- **한계** — 정지·손 없음이라 실제 장면보다 가볍다(손 랜드마크 0% · 버튼 검출 0). 손·공구가 보이는 장면은 장소2 에서(계획 Task 2-2).
- 공구 검출 — 장면에 공구가 없어 모든 회차 0(≥0.65) · 오검출도 0.

- 정리 — 한 번 추론은 NPU 가 약 10~20배(혼자 190 → 10ms · 함께 400 → 19ms) 빠르다. 1초 간격에서는 **평균 FPS 차이가 없다**(CPU 공구는 별도 프로세스라 줄을 막지 않는 대신 파이 CPU 를 약 +18%p 쓰고 손 처리를 약 1.7ms 늦춘다 · NPU 공구는 CPU 를 비우는 대신 공구를 돈 다음 한 장이 느려진다). 공구 결과가 나오기까지의 지연은 NPU 가 짧다(약 0.4초 → 0.02초). 장면이 정지·손 없음이라 실제 장면은 장소2 에서.
